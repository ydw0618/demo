# 同频 Relay · AI 客服 Agent 与人机协同平台

可交互双端原型，全部业务数据与 AI 回复由浏览器规则模拟，不使用真实模型、企业 API 或支付服务。

## 运行

下载或克隆本仓库后，用浏览器打开 `relay-prototype.html` 即可体验单文件演示版；打开 `dist/index.html` 可运行分离源码版。也可从项目目录运行 `node server.cjs`，在浏览器访问 http://localhost:4173 。

本仓库仅保存原型与文档，未配置 GitHub Pages 或真实业务后端。

## 推荐演示路径

1. 工作台默认展示林晓的高风险投诉及四字段 AI 摘要。高级客服接入后，系统发送已阅读历史的默认话术。
2. 采用 Copilot 草稿，编辑并发送。右侧查看客户、订单及政策，标记摘要有误。
3. 创建售后时确认已获得客户授权；工单创建后，在 C 端及售后工单页检查回执。重复提交复用已有申请。
4. C 端点击「从 AI 售后开始」，重走查询订单、知识引用、方案确认、自助提交的流程。
5. C 端输入「我要投诉」或「转人工」后，切换客服端，检查历史和摘要已同步。
6. 开启「模拟接口异常」后查询订单，测试失败提示、重试与转人工。输入「超时」触发 AI 超时兜底，非已知问题触发无法可靠回答转人工。
7. 在未接入的高风险会话切换为普通客服，接入会被阻止。

## 21 个 C 端交互组件

快捷意图入口、客户文本消息、AI 身份与状态、输入发送栏、订单结果卡、售后方案卡、来源引用卡、引用原文弹窗、点赞、点踩、售后确认弹窗、申请回执、物流状态、接口异常卡、失败重试、主动转人工、排队状态、人工接入提示、人工回复、结束状态、隐私与 AI 提示。

## 数据与实现边界

- 演示状态通过 localStorage 保存在当前浏览器，可切换双端或同源标签页查看。同浏览器不同标签页会同步存储事件；不同设备与不同浏览器不共享状态。
- 业务数据、角色切换和权限阻止只用于原型演示，不能充当生产安全校验。
- 同一订单只创建一个售后申请，状态止于待审核，不执行退款。
- 排序按风险降序、等待时间降序；初始等待分钟为固定演示值，不是实时 SLA 计时。
- 林晓为完整可操作场景，其他三个会话仅用于演示队列、排序和状态分组，标为只读。
- 数据概览中的成效数字来自用户项目材料，并非原型实测。上下文断层客诉数与重复描述率需要分别统计。
- 产品接口草案包含订单、知识检索、售后创建和转交。生产环境需要后端完成登录鉴权、会话归属、角色权限、幂等、真实状态机、持久化、审计、模型调用与退款审批。
- API 密钥不得放在浏览器前端。本原型不包含任何模型或业务密钥。

## 文件

`dist/index.html`、`dist/styles.css`、`dist/app.js` 为静态页面源码；`relay-prototype.html` 为独立演示文件；`server.cjs` 为本地静态预览服务。仓库不包含本地托管身份配置。
